## 过程记录
### NanoBot 最小流程链路：
第 1 步：先建立全局地图（30 分钟）
读 AGENTS.md + .agent/design.md（架构约束）。然后只记住数据流骨架：
```
Channel → InboundMessage → MessageBus → AgentLoop → AgentRunner → LLM/Tools → 回复 → MessageBus → OutboundMessage
```

第 1 步：读懂"那根线"（最核心，按此顺序）
1. `nanobot/bus/queue.py`（仅 148 行）— 消息总线。这是解耦的枢纽，先懂它，channel 和 agent 才能分开理解。
2. `nanobot/events.py`（95 行）— `InboundMessage/OutboundMessage` 数据结构，全仓库的"货币"。
3. `nanobot/agent/loop.py`（2549 行，先读骨架不看细节）— 找到"收到消息→构建上下文→交给 runner→发回复"的主函数。这是编排层。
4. `nanobot/agent/runner.py`（1383 行）— 整个系统的心脏：多轮 LLM 循环（发 prompt → 收 tool call → 执行 → 再发 → 直到无 tool call）。读懂这个，agent 的本质就懂了。
读完这 4 个，你已经掌握了"一条消息如何变成回复"的全部主干。其余都是扩展。

第 2 步：理解三个关键抽象
1. `nanobot/providers/base.py` — `LLMProvider` 接口。配合上一轮看的 `registry.py+factory.py`，你就懂了"如何屏蔽 30+ 厂商"。
2. `nanobot/agent/tools/registry.py`（212 行）+ 任选一个工具读（建议 `nanobot/agent/tools/` 下最简单的一个）— 工具如何注册、如何被 LLM 调用、`pkgutil` 自动发现机制。
3. `nanobot/config/schema.py` — `Pydantic` 配置模型。它是所有行为的"调音台"，读懂它才能改任何行为。

第 3 步：状态与持久化
4. `nanobot/agent/memory.py` + `nanobot/session/manager.py` — 记忆、会话历史、上下文压缩（compaction）。这是 agent "有状态"的来源，也是最难的部分。
5. `nanobot/agent/context.py`（363 行）— 上下文如何拼装（system prompt + 历史 + 工具 + 技能）。

第 4 步：扩展面（按需读）
- Channel：读 `nanobot/channels/base.py`（341 行）+ 挑一个最简单的 channel（如 WebSocket/Email）看接入模式。
- 命令路由：`nanobot/command/router.py`（170 行）。
- WebUI/网关：`nanobot/gateway/` + `webui/`（React，WS 多路复用协议）。

学习心法
1. 先主干后枝叶：别一上来读 channel 或 WebUI，它们是"皮肤"，runner 才是"器官"。
2. 用测试当文档：tests/ 镜像源码结构，读某个模块前先看对应 test，能看清预期行为。
3. 跟一次真实调用：在 `runner.py` 的主循环里打断点/加日志，跑一条消息，观察消息在 `bus↔loop↔runner` 间如何流转。
4. 抓住"自发现"模式：channel 和 tool 都用 pkgutil 扫描 + entry-point 插件，这是本仓库反复出现的扩展范式，读懂一处通一处。
最短路径：如果只有 2 小时，就精读 `queue.py` → `events.py` → `runner.py` 的主循环 → `context.py`。这四块通了，其余代码都能快速定位。
